# Follow-ups

File a follow-up with `create_follow_up` only when the problem is real,
separate from the current task, and worth tracking (a bug, missing test,
tech debt with impact). Give it a clear title, where it is, and why it
matters. Small fixes inside the task's scope belong in the task, and
speculative ideas belong in the summary, not in the backlog.
